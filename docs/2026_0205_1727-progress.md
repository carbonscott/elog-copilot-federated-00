# Elog-Copilot PostgreSQL Prototype - Memory

## Project Setup
- PostgreSQL 16 installed via micromamba at `pg_env/`, data at `pg_data/`, port 5434
- Trust auth (no passwords) for local development
- Manage server: `bash scripts/setup_postgres.sh start|stop|status`
- Connect: `pg_env/bin/psql -h /tmp -p 5434 -d elog_prototype`

## Key Facts
- SQLite source (canonical): `/sdf/group/lcls/ds/dm/apps/dev/data/elog-copilot/elog-copilot.db` (symlink to latest)
- Used snapshot `elog_2026_0204_1800.db` for initial testing
- ~4.85M rows: 1,842 experiments, 443K runs, 710K logbook, 3.1M run_detectors, 109K questionnaire, 2.6K workflows, 484 detectors
- Migration takes ~2.3 minutes at ~42K rows/s

## Known Issues & Lessons
- **NUL bytes in SQLite text**: Logbook content contains `\x00` characters. Must strip before PG insert (PG TEXT cannot contain NUL).
- **micromamba cache**: Scratch disk at `/sdf/scratch/` is often full (100GB limit). Use `CONDA_PKGS_DIRS` and `MAMBA_ROOT_PREFIX` to redirect to data disk.
- **micromamba prefix conflict**: micromamba's `create -p` needs a clean directory. Keep micromamba binary in `pg_tools/`, not inside the env prefix.
- **`trigger` is a PG reserved word**: Must be double-quoted `"trigger"` in DDL and queries for the workflows table.
- **FORCE ROW LEVEL SECURITY**: Blocks even the table owner. Must `GRANT elog_admin TO <superuser>` for migration/admin to work.
- **RLS query plans**: Currently using seq scans on user_experiment_access for username filter. Index `idx_user_access_username` exists but PG prefers hashed subplan for small tables. Acceptable for prototype.
